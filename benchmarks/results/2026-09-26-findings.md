# CPU baseline: 26 September 2026

The study contains 240 validated configurations and 12 explicitly unsupported
Python/custom-model configurations. No numerical comparison failed. The largest
shared-increment discrepancy across all validated configurations was
6.439e-15.

Raw data and generated tables:

- [Three-family pilot](2026-09-26-cpu-pilot/summary.md)
- [65,536-particle moment case](2026-09-26-large-moments/summary.md)

## Comparable warm timings

These are milliseconds for 128 Euler steps with one logical CPU allowed,
float64, the same noise and initial/final output. Each entry is the median
of three independent-seed warm medians, each based on seven repetitions.

| Case | N | d | Rust core | Python wrapper | NumPy | Numba | Diffrax | SciML |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| moments | 4,096 | 1 | 4.486 | 4.466 | 1.816 | 1.143 | 0.373 | 3.463 |
| pairwise | 128 | 2 | 112.249 | 113.870 | 137.471 | 30.977 | 63.202 | 56.607 |
| multiplicative | 2,048 | 4 | 6.514 | unsupported | 8.260 | 1.441 | 1.835 | 4.977 |
| moments | 65,536 | 1 | 46.783 | 73.350 | 13.840 | 17.439 | 8.182 | 55.449 |

These results establish a performance gap for the current implementations.
For the 4,096-particle moment case, the Rust core takes
12.0 times the warm execution time of Diffrax. At 65,536 particles,
the ratio is 5.7.
The compiled Numba loops are also useful optimization targets, especially
for pairwise interactions. These are comparisons of the listed implementations,
not universal rankings of their libraries.

## Effect of the CPU budget

| Case | N | Rust core, 1 CPU (ms) | Rust core, 4 CPUs (ms) | Speedup, 1 CPU / 4 CPUs |
|---|---:|---:|---:|---:|
| moments | 4,096 | 4.486 | 11.198 | 0.40x |
| pairwise | 128 | 112.249 | 42.358 | 2.65x |
| multiplicative | 2,048 | 6.514 | 14.272 | 0.46x |
| moments | 65,536 | 46.783 | 48.581 | 0.96x |

A value below 1 means the four-CPU run was slower. The benefit of parallelism
depends strongly on the interaction cost. The large moment case is close to
parity in this environment, so a universal particle-count threshold should not
be selected from the small pilot alone.

## Next profiling and optimization targets

1. **Fuse simple updates.** The generic Rust integrator fills drift, diffusion
   and noise buffers before traversing them again to update the state. Profile
   this memory traffic and introduce a specialized fused path where the model
   structure permits it, retaining the generic trait implementation.
2. **Choose parallel granularity from work.** Test a sequential path and
   chunked parallel loops against the same cases. Pairwise interactions and
   moment interactions need different work estimates.
3. **Measure Python input-copy costs.** In the 65,536-particle case, the
   existing wrapper takes
   73.350 ms against 46.783 ms for the core with one CPU.
   The current wrapper copies the full supplied increment array, which is
   64 MiB in that configuration. Profile ownership/conversion costs before
   redesigning this interface; preserve safe ownership when releasing the GIL.
4. **Profile the all-pairs kernel.** Its temporary per-particle accumulator
   allocation and repeated ndarray access are candidates, alongside the power
   function and memory layout. The timing gap alone does not attribute a
   measured share to any individual operation.

The simulation implementation is unchanged by this study. These are profiling
priorities inferred from measurements and code inspection, not measured
speedups from an optimization patch.

## Scope and reproducibility

The machine reports an AMD EPYC 9V74 CPU in a container with an eight-CPU quota.
Workers used one or four allowed logical CPUs; the host was not a dedicated
benchmark machine. Exact settings, versions, fingerprints, per-seed ranges,
first-call costs and process memory measurements are retained with the data.

The Rust release build uses portable target settings. JIT backends specialize
to the case and shape; compilation appears in first-call measurements. Warm
solver timing excludes input generation, imports, device preparation and
output serialization. This study does not time native random generation,
compare GPU execution, or optimize each library over adaptive/higher-order
solvers. The reference is a coupled finer Euler trajectory, not an exact
solution or a certified statistical error bound.

Reproduce the pilot using the command in [the benchmark guide](../README.md).
For the large moment case, use the same backends, seeds, threads and repetitions
with `--cases moments --particles 65536 --steps 128` and a fresh output directory.
